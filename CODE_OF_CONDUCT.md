# Code of Conduct

## The short version

Be decent to people. Assume good faith. Disagree about the work, not about the
person.

## What we expect

This project depends on contributions from accountants, attorneys, nonprofit
staff, and developers — people with very different backgrounds, working in
whatever time they can spare. That mix only works if it is comfortable to
participate.

- **Welcome inexperience.** Someone who knows Washington charity law but has
  never used git is exactly the contributor this project needs. "You should have
  opened a pull request" is not a useful response to a correct issue.
- **Be specific and kind in review.** Rule review is fact-checking, not
  criticism. "This cites RCW 24.03A.1010 but that section covers X" is helpful;
  "this is wrong" is not.
- **Say when you are unsure.** Marking a rule `draft` because you have not read
  the statute is a contribution, not a failure. Nobody is expected to know all
  fifty states.
- **Accept correction.** Everyone here will be wrong about a filing deadline at
  some point, including maintainers.

## What is not acceptable

Harassment, personal attacks, discriminatory or demeaning comments, sustained
disruption, publishing others' private information, or unwelcome sexual
attention. This applies in issues, pull requests, discussions, commit messages,
and any other project space.

## Reporting

Email **conduct@stonedogcode.com**. Reports are read by StoneDogCode L.L.C. and
handled confidentially. You will get a response.

Maintainers may remove comments, close pull requests, or block accounts that
breach this document. We would much rather have a quiet word first, and usually
will.

## Scope

Applies to everyone in project spaces, maintainers included, and to public
spaces where someone is representing the project.
